# 筛选决策引擎

## 一、需求解析规则

从用户自然语言中提取筛选条件，映射为工具参数。

### 1.1 类别关键词映射

| 用户表述 | SearchFunds category 参数 |
|---------|--------------------------|
| "偏股""股票型""权益" | 偏股型 |
| "指数""ETF""被动" | 指数型 |
| "债券""纯债""固收" | 债券型 |
| "货币""余额""活期" | 货币型 |
| "QDII""海外""美股""港股" | QDII型 |
| "混合""平衡" | 平衡混合型 |
| "偏债混合""固收+" | 偏债混合型 |
| "黄金""商品" | 商品型 |
| 子类别："纯债""一级债""二级债" | 纯债 / 一级债 / 二级债 |
| 子类别："可转债" | 可转债 |

| 用户表述 | SearchFunds sortColumn 参数 | sortOrder |

| "回撤小""稳健""波动小" | — （需筛选后二次过滤） | — |

| "七日年化高"（货币型） | 七日年化收益率 | 降序 |

### 1.3 数值条件提取

| 用户表述模式 | 提取规则 | 示例 |
|------------|---------|------|
| "大于/超过/不低于 X" | operator = "gte", threshold = X | "规模大于10亿" → 基金规模 ≥ 10 亿 |
| "小于/低于/不超过 X" | operator = "lte", threshold = X | "换手率低于200%" → 换手率 ≤ 200% |
| "X 到 Y 之间" | operator = "between", threshold = [X, Y] | "规模 5~20 亿" → 规模 ∈ [5, 20] |
| "前 X 名" / "Top X" | 筛选后取前 X 条 | "收益前10" → 按收益排序取前 10 |

## 二、MCP 工具选择矩阵

### 2.1 按筛选场景选择工具组合

#### 通用基金筛选

```
SearchFunds(category, sortColumn, sortOrder, size=20)
    → BatchGetFundsDetail(前 N 只代码)
    → GetBatchFundPerformance(前 N 只代码)
    → 综合排序
    → BatchGetFundTradeLimit(Top 推荐代码) 确认可买
```

#### 股票型基金筛选

```
SearchFunds(category="偏股型", sortColumn="近一年收益", sortOrder="降序")
    → 可选叠加: filterStockFundByStockTurnover(换手率条件)
    → BatchGetFundsDetail + GetBatchFundPerformance
    → AnalyzeFundRisk(候选基金)
    → 综合排序 → Top 推荐
```

#### 债券型基金筛选

```
SearchFunds(category="债券型")
    → filterBondFundByBondType(券种偏好) 缩小范围
    → filterBondFundByCreditRating(评级要求) 再次过滤
    → 取交集
    → GetBatchFundPerformance 获取业绩
    → 综合排序 → Top 推荐
```

#### 债基排雷

```
getBondFundWithAlertRecord(bondAlterType, divingThreshold)
    → BatchGetFundsDetail(告警基金代码)
    → 按告警严重程度排序
    → 输出排雷报告
```

#### 热门基金推荐

```
GetPopularFund(size=10~20)
    → BatchGetFundsDetail(热门基金代码)
    → GetBatchFundPerformance(热门基金代码)
    → 综合排序 → 输出推荐
```

#### 关联策略查找

```
GetFundRelatedStrategies(fundCode / fundName)
    → GetStrategyDetails(策略代码列表)
    → 输出策略列表及配置比例
```

### 2.2 叠加条件的工具组合策略

当用户给出多个筛选条件时，按以下优先级组合工具：

| 优先级 | 条件类型 | 工具 | 说明 |
|--------|---------|------|------|
| 1 | 基金类别 | SearchFunds(category) | 先确定大类 |
| 2 | 排序维度 | SearchFunds(sortColumn) | 在大类内排序 |
| 3 | 券种/评级（债券型） | filterBondFundByBondType / filterBondFundByCreditRating | 专项过滤 |
| 4 | 换手率（股票型） | filterStockFundByStockTurnover | 专项过滤 |
| 5 | 风险/回撤/波动 | GetBatchFundPerformance → 程序过滤 | 二次过滤 |
| 6 | 规模区间 | SearchFunds 结果 → 按规模过滤 | 二次过滤 |

多条件叠加时，前几步得到的结果集取交集，然后用增强工具做最终排序。

## 三、结果排序与推荐规则

### 3.1 综合得分算法

对筛选出的基金按以下权重计算综合得分（百分制）：

| 维度 | 权重 | 数据来源 | 评分规则 |
|------|------|---------|---------|
| 收益能力 | 40% | GetBatchFundPerformance | 近 1 年同类排名百分位：前 10% = 100 分，前 20% = 80 分，前 40% = 60 分，前 60% = 40 分，后 40% = 20 分 |
| 风险控制 | 30% | GetBatchFundPerformance / AnalyzeFundRisk | 夏普比率同类排名百分位，评分规则同上 |
| 规模适中 | 15% | BatchGetFundsDetail | 2~200 亿 = 100 分；200~500 亿 = 80 分；1~2 亿 = 40 分；< 1 亿 = 0 分（排除） |
| 费率优势 | 15% | BatchGetFundsDetail | 同类费率排名百分位：前 20% = 100 分；前 50% = 60 分；后 50% = 30 分 |

**最终得分** = 收益能力 × 0.4 + 风险控制 × 0.3 + 规模适中 × 0.15 + 费率优势 × 0.15

### 3.2 去重规则

| 规则 | 判定条件 | 处理 |
|------|---------|------|
| 同经理同类型 | 同一基金经理管理的同类基金 | 仅保留综合得分最高的一只 |
| A/C 份额 | 同一基金的不同份额 | 默认保留 A 份额，用户问费率时保留 C 份额 |
| 高度相关 | GetFundsCorrelation 相关系数 > 0.9 | 保留综合得分更高的一只 |

### 3.3 排除规则（强制）

| 排除条件 | 原因 |
|---------|------|
| 规模 < 1 亿 | 清盘风险 |
| 暂停申购 | 不可买入 |
| 成立不足 6 个月 | 数据不充分 |
| 基金已清盘/终止 | 不可买入 |

### 3.4 推荐数量

| 场景 | 推荐数量 | 说明 |
|------|---------|------|
| 通用筛选 | 5~8 只 | 足够对比又不过多 |
| 细分领域筛选 | 3~5 只 | 候选池较小 |
| 热门推荐 | 6~10 只 | 覆盖多品类 |
| 债基排雷 | 不限 | 全部列出 |

## 四、债基排雷专题

### 4.1 告警类型说明

| 告警类型 | 含义 | 典型原因 |
|---------|------|---------|
| dailyDive（日跳水） | 单日净值大幅下跌 | 重仓债券违约、估值调整、大额赎回冲击 |
| weekDive（周跳水） | 一周内累计跌幅较大 | 持续性信用风险暴露、流动性危机 |
| unusual（异动） | 净值出现异常波动 | 可能的信用事件、市场冲击、运营风险 |

### 4.2 阈值说明

#### 日跳水阈值

| 阈值 | 跌幅 | 严重程度 |
|------|------|---------|
| -0.0005 | -0.05% | 轻微 |
| -0.001 | -0.1% | 偏低 |
| -0.002 | -0.2% | 中等 |
| -0.005 | -0.5%（默认） | 较严重 |
| -0.01 | -1% | 严重 |

#### 周跳水阈值

| 阈值 | 跌幅 | 严重程度 |
|------|------|---------|
| -0.0025 | -0.25% | 轻微 |
| -0.005 | -0.5% | 偏低 |
| -0.01 | -1%（默认） | 较严重 |
| -0.02 | -2% | 严重 |
| -0.03 | -3% | 非常严重 |

### 4.3 风险解读规则

对排雷结果按以下规则输出解读：

| 告警特征 | 解读 | 建议 |
|---------|------|------|
| 日跌幅 > 0.5% 的纯债基金 | "出现显著净值回撤，可能存在持仓信用风险" | 建议排查重仓债券信用状况 |
| 周跌幅 > 1% 的纯债基金 | "连续多日下跌，可能面临持续性风险" | 建议持有人关注并评估是否赎回 |
| 异动记录 | "净值出现非正常波动，原因待确认" | 建议关注基金公告，了解异动原因 |
| 同一基金多次触发告警 | "多次出现告警，风险较为集中" | 建议高度警惕，密切关注 |
| 规模较小（< 2 亿）+ 告警 | "规模偏小叠加净值异常，流动性风险较高" | 建议谨慎持有 |

### 4.4 排雷报告必须包含

1. 告警基金列表（代码、名称、类型、规模）
2. 告警类型（日跳水 / 周跳水 / 异动）
3. 告警时间或最近发生日期
4. 跌幅数据
5. 风险解读（根据 4.3 规则）
6. 建议操作
7. 免责声明

## 五、错误处理与边界场景

### 5.1 筛选无结果

| 场景 | 处理方式 |
|------|---------|
| 条件组合无匹配 | 执行 SKILL.md 中“多条件筛选交集为空回退算法（4 步）”，并在输出中说明每一步放宽了哪些条件 |
| 单一条件无匹配 | 调整参数范围后重试一次，仍无结果则明确告知用户 |
| 类别不存在 | 列出支持的基金类别，让用户重新选择 |

### 5.2 筛选结果过多

| 场景 | 处理方式 |
|------|---------|
| 初筛 > 50 只 | 执行 SKILL.md 中“结果收敛算法”：按关注维度排序 → 截断 Top30 → 强制排除规则 → 风险/相关性二次过滤后输出 Top5~8 |
| 排雷结果 > 30 只 | 按告警严重程度排序，优先展示最严重的，其余折叠 |

> 说明：为避免多版本规则冲突，本文件在“交集为空回退”和“候选过多收敛”场景下，均以 `fund-screener/SKILL.md` 的算法定义为唯一标准。

### 5.3 工具调用异常

| 场景 | 处理方式 |
|------|---------|
| SearchFunds 失败 | 提示搜索服务暂时不可用，建议稍后重试 |
| 筛选工具（filter 系列）失败 | 跳过该维度筛选，用 SearchFunds 结果替代，标注"XX维度筛选暂不可用" |
| 增强工具（Detail/Performance）失败 | 用已有基础数据输出，标注缺失的信息 |
| BatchGetFundTradeLimit 失败 | 输出推荐但标注"交易状态未确认，请购买前自行核实" |

### 5.4 用户意图模糊

| 场景 | 处理方式 |
|------|---------|
| "帮我推荐基金"（无任何条件） | 引导用户选择：① 基金类型偏好 ② 风险承受能力 ③ 投资期限 |
| 条件相互矛盾（如"低风险高收益"） | 指出矛盾，说明"低风险通常对应较低收益"，引导调整预期 |
| 不支持的筛选维度 | 列出当前支持的筛选维度，让用户重新表述 |

### 5.5 数据时效性

- 基金业绩数据通常滞后 1~2 个交易日，排雷告警数据为近期记录
- 输出中统一标注"数据截至 YYYY-MM-DD"
- 规模数据以最近一期报告为准，标注报告日期
