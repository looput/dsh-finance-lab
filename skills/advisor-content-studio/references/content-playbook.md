# 内容创作引擎

## 一、内容类型识别与素材工具矩阵

### 1.1 内容类型识别

收到用户输入后，按以下规则识别内容类型：

| 优先级 | 关键词/特征 | 识别为 | 说明 |
|-------|-----------|--------|------|
| 1 | 明确提到"市场解读""行情分析""大盘" | 市场解读 | 需要行情数据 + 深度分析 |
| 2 | 提到"推荐""基金""选基""配置" | 基金推荐 | 需要基金数据 + 分析支撑 |
| 3 | 提到"科普""什么是""怎么理解""入门" | 投教科普 | 概念解释为主 |
| 4 | 提到热点事件 + "评论""看法""影响" | 热点评论 | 时效性优先 |
| 5 | 提到"朋友圈""文案""社群""短文" | 短文案 | 精炼文案 |
| 6 | 提到"选题""写什么""灵感" | 选题发现 | 输出选题清单 |
| 7 | 提到"排版""HTML""PDF""美化" | 排版输出 | 对已有内容排版 |

**歧义处理**：无法确定类型时，向用户追问："您需要创作哪种类型的内容？1. 市场解读 2. 基金推荐 3. 投教科普 4. 热点评论 5. 短文案"

### 1.2 素材工具矩阵

每种内容类型对应不同的 MCP 工具组合：

#### 市场解读

| 调用顺序 | 工具 | 参数要点 | 用途 | 必选 |
|---------|------|---------|------|------|
| 1 | `GetLatestQuotations` | `calDate`: 目标日期 | 获取各市场行情数据 | ✅ |
| 2 | `SearchFinancialNews` | `keyword`: 相关关键词 | 搜集新闻背景与事件 | ✅ |
| 3 | `SearchManagerViewpoint` | `keyword`: 市场/行业关键词 | 获取经理观点引用 | ⬜ |
| 4 | `searchRealtimeAiAnalysis` | `keyword`: 相关关键词 | AI 解读角度参考 | ⬜ |

#### 基金推荐

| 调用顺序 | 工具 | 参数要点 | 用途 | 必选 |
|---------|------|---------|------|------|
| 1 | `SearchFunds` / `GuessFundCode` | 主题/名称关键词 | 确定基金代码 | ✅ |
| 2 | `BatchGetFundsDetail` | `fundCodes`: 基金代码列表 | 获取基金基本信息 | ✅ |
| 3 | `GetBatchFundPerformance` | `fundCodes`: 基金代码列表 | 获取业绩表现数据 | ✅ |
| 4 | `BatchGetFundsHolding` | `fundCodes`: 基金代码列表 | 获取持仓信息 | ⬜ |
| 5 | `AnalyzeFundRisk` | `fundCodes`: 基金代码列表 | 风险评估数据 | ⬜ |
| 6 | `SearchManagerViewpoint` | `keyword`: 基金经理/主题 | 经理观点引用 | ⬜ |

#### 投教科普

| 调用顺序 | 工具 | 参数要点 | 用途 | 必选 |
|---------|------|---------|------|------|
| 1 | `searchInvestAdvisorContent` | `keyword`: 科普主题 | 已有优质内容参考 | ⬜ |
| 2 | `SearchManagerViewpoint` | `keyword`: 相关主题 | 经理观点佐证 | ⬜ |

投教科普以概念解释和逻辑论述为主，MCP 工具数据为辅助佐证。

#### 热点评论

| 调用顺序 | 工具 | 参数要点 | 用途 | 必选 |
|---------|------|---------|------|------|
| 1 | `SearchHotTopic` | `keyword`: 热点关键词 | 热点事件详情 | ✅ |
| 2 | `SearchFinancialNews` | `keyword`: 事件关键词 | 新闻背景补充 | ✅ |
| 3 | `GetLatestQuotations` | 默认参数 | 行情数据佐证 | ⬜ |
| 4 | `searchRealtimeAiAnalysis` | `keyword`: 热点关键词 | AI 解读参考 | ⬜ |

#### 短文案

短文案根据主题内容选择对应工具，通常只需 1-2 个：
- 推荐基金类 → `BatchGetFundsDetail` + `GetBatchFundPerformance`
- 市场相关类 → `GetLatestQuotations`
- 热点相关类 → `SearchHotTopic`

#### 选题发现

| 调用顺序 | 工具 | 用途 | 必选 |
|---------|------|------|------|
| 1 | `SearchHotTopic` | 发现当前热点话题 | ✅ |
| 2 | `SearchFinancialNews` | 发现新闻热点 | ✅ |
| 3 | `searchRealtimeAiAnalysis` | 发现分析角度 | ⬜ |
| 4 | `searchInvestAdvisorContent` | 排除已有内容、发现缺口 | ⬜ |

## 二、创作规则与写作框架

### 2.1 市场解读

**写作结构**：

```
一、行情回顾（数据开头）
   - 主要指数涨跌幅数据（来自 GetLatestQuotations）
   - 成交量变化
   - 板块涨跌排行

二、原因分析
   - 政策面/消息面因素（来自 SearchFinancialNews）
   - 资金面/技术面因素
   - 行业/板块驱动因素

三、机构观点
   - 引用 2-3 位基金经理观点（来自 SearchManagerViewpoint）
   - 标注来源：经理姓名 + 基金公司

四、后市展望
   - 基于数据和观点的综合判断
   - 关注要点提示（不做收益预测）

免责声明
```

**字数要求**：1500-3000 字
**写作规范**：
- 开头第一段必须包含具体数据（指数点位、涨跌幅）
- 中间分析部分不能全是观点堆砌，需穿插数据佐证
- 经理观点引用格式：`XX基金XX经理认为："引用原文"（来源：SearchManagerViewpoint）`
- 结尾不做方向性预判（如"明天将上涨"），可做风险提示
- 使用专业但不晦涩的语言，面向有一定基础的投资者

### 2.2 基金推荐

**写作结构**：

```
一、痛点/场景切入
   - 从投资者需求或市场热点引入
   - 为什么现在适合关注这类基金

二、基金亮点概述
   - 推荐基金的核心卖点（2-3 个）
   - 基金经理简介

三、数据支撑
   - 业绩表现（阶段收益、同类排名）—— 来自 GetBatchFundPerformance
   - 风险指标（最大回撤、波动率、夏普比率）—— 来自 AnalyzeFundRisk
   - 持仓特点（重仓行业/个股）—— 来自 BatchGetFundsHolding

四、风险提示（必须包含）
   - 该基金的主要风险点
   - 适合什么类型的投资者
   - 建议持有期限

免责声明
```

**字数要求**：1000-2000 字
**写作规范**：
- 禁止使用"保证收益""稳赚不赔""预计涨XX%"等收益承诺表述
- 业绩数据必须标注截止日期："截至XXXX年XX月XX日"
- 风险提示段不能敷衍，需具体到该基金的风险特征
- 推荐多只基金时（≤5 只），每只需有独立的数据支撑
- 排名引用格式："近一年收益XX%，同类排名前XX%（数据来源：盈米且慢，截至XXXX-XX-XX）"

### 2.3 投教科普

**写作结构**：

```
一、生活类比引入
   - 用日常生活场景类比投资概念
   - 激发读者兴趣

二、概念解释
   - 通俗语言解释核心概念
   - 关键术语加粗标注

三、实例说明
   - 用具体案例帮助理解
   - 可引用经理观点佐证

四、注意事项
   - 常见误区提醒
   - 实操建议
```

**字数要求**：800-1500 字
**写作规范**：
- 语言通俗易懂，避免堆砌专业术语
- 关键概念首次出现时给出解释
- 使用"比如""举个例子"等衔接词增强可读性
- 可以使用类比和比喻，但必须准确（不能因简化而产生误导）
- 引用的经理观点用于佐证，不能作为主体内容

### 2.4 热点评论

**写作结构**：

```
一、事件概述
   - 热点事件是什么（来自 SearchHotTopic / SearchFinancialNews）
   - 核心信息提炼

二、影响分析
   - 对市场/行业的影响
   - 行情数据佐证（来自 GetLatestQuotations）

三、投资启示
   - 投资者应该关注什么
   - 风险提示

免责声明
```

**字数要求**：500-1000 字
**写作规范**：
- 时效性优先，快速成文
- 事件描述客观中立，不带主观情绪
- 影响分析需有数据佐证，不能纯猜测
- 投资启示给方向不给具体操作指令

### 2.5 短文案

**写作结构**：核心观点（1 句）+ 数据亮点（1-2 个）+ 行动引导（1 句）

**字数要求**：100-300 字
**写作规范**：
- 第一句话必须抓人眼球
- 数据点精炼，选最有说服力的 1-2 个
- 行动引导语气温和（"了解一下"优于"赶紧买"）
- 基金推荐类短文案也需要风险提示（可简化为一句）
- 适合直接复制到朋友圈/社群使用

## 三、排版与输出规则

### 3.1 HTML 样式规范

生成 HTML 时，**原样复制** [report-templates.md](report-templates.md) 的「通用 HTML 基座」作为外壳，将 `<!-- CONTENT -->` 替换为对应内容类型的「板块 HTML」。

CSS 和 JS 已完整内嵌于基座中，**严禁修改、删减或自行编写任何 CSS/JS**。最终效果必须与 [demo-report.html](../../yingmi-skill/references/demo-report.html) 视觉一致。

**组装步骤**：
1. 原样复制 report-templates.md 的通用 HTML 基座（`<!DOCTYPE html>` 到 `</html>`）
2. 替换 `<title>` 中的 `{{标题}}` 和 `{{日期}}`
3. 替换 `<!-- CONTENT -->` 为对应模板的板块 HTML
4. 替换 `// BINDCHARTS` 为对应模板的 ECharts 初始化代码
5. 替换所有 `{{占位符}}` 为 MCP 工具返回的真实数据

**禁止事项**：
- 禁止自行编写 CSS（`<style>` 中的内容不可增删改）
- 禁止自创 HTML 类名（必须使用 demo-report.html 和 report-templates.md 中已定义的组件类名）
- 禁止省略通用基座中的任何部分（Google Fonts、CSS 变量、暗色主题等）

### 3.2 ECharts 图表配置

ECharts 初始化代码放入通用基座 `// BINDCHARTS` 位置。每种内容类型模板均提供了对应的 ECharts 代码示例。

**通用规则**：
- CDN 已在基座 `<head>` 中引入：`echarts@5.5.0`
- 颜色使用基座中的 `chartColors` 数组和辅助函数：`tc()` 正文色、`ttc()` 标题色、`lc()` 标签色、`gc()` 分割线色
- 深浅色切换时 `renderAll()` 会自动 `dispose` 所有图表并重新初始化
- 所有 ECharts 实例必须 `charts.push()` 以支持 resize 和主题切换

**常用图表类型**：

| 场景 | 图表类型 | 容器类名 |
|------|---------|---------|
| 板块涨跌幅 | 水平柱状图 | `.chart-full` |
| 成交额走势 | 折线图 + 面积 | `.chart-box`（双列之一） |
| 北向资金 | 柱状图 | `.chart-box`（双列之一） |
| 基金收益对比 | 分组柱状图 | `.chart-full` |
| 资产配置 | 环形饼图 | `.chart-box` |

### 3.3 长图输出流程

1. 先生成标准 HTML（使用通用基座 + 板块模板）
2. 确保页面使用浅色主题（`data-theme="light"`）
3. 调用工具基于 HTML 生成高清长图：
   - 使用设备最高清晰度渲染
   - 包含背景和样式（`printBackground: true`）
   - 等待 ECharts 完全加载后再截图
4. 返回长图或在对话中直接输出呈现

## 四、合规红线

### 4.1 禁止表述清单

以下表述**绝对禁止**出现在任何内容中：

| 类别 | 禁止表述示例 |
|------|-----------|
| 收益承诺 | "预计涨XX%""保证收益""稳赚不赔""绝对回报" |
| 过度推荐 | "必买""不买就亏了""抄底机会""最后的上车机会" |
| 虚假数据 | 编造不存在的业绩数据、排名数据 |
| 不当比较 | "比银行存款强多了""完胜理财产品" |
| 确定性判断 | "明天一定涨""这个板块必定起飞" |

### 4.2 替代表述指南

| 禁止表述 | 替代表述 |
|---------|---------|
| "这只基金一定能赚钱" | "从历史数据来看，该基金近X年业绩表现优于同类平均" |
| "现在是最佳买入时机" | "从估值角度看，当前处于近X年较低区间" |
| "预计明年涨30%" | "XX经理认为该板块中长期具有配置价值（来源：XX）" |
| "赶紧买" | "感兴趣的投资者可进一步了解" |

### 4.3 必须包含的声明

**免责声明**（每篇内容末尾必须出现）：

> 免责声明：以上内容基于公开数据和已发布观点整理，仅供参考，不构成投资建议。基金有风险，投资需谨慎。数据来源：盈米且慢。

**风险提示**（基金推荐类额外要求）：
- 必须提及该基金的具体风险特征（如集中度高、波动大、规模小等）
- 必须说明适合的投资者类型和建议持有期
- 必须标注"基金过往业绩不预示未来表现"

## 五、错误处理与降级策略

### 5.1 素材搜集阶段

| 场景 | 降级策略 | 输出处理 |
|------|---------|---------|
| `GetLatestQuotations` 失败 | 用 `SearchFinancialNews` 中的行情描述替代 | 标注"行情数据暂未获取，以下基于新闻报道" |
| `SearchFinancialNews` 返回空 | 扩大关键词范围重试；仍无结果则跳过新闻引用 | 标注"近期无相关新闻报道" |
| `SearchManagerViewpoint` 返回空 | 用 `searchRealtimeAiAnalysis` 替代 | 引用来源改为"AI 分析" |
| `BatchGetFundsDetail` 失败 | 提示用户确认基金代码 | 不输出内容，要求用户核实 |
| `GetBatchFundPerformance` 失败 | 用 `BatchGetFundsDetail` 中的基础业绩数据 | 标注"详细业绩数据暂未获取" |
| 多个工具连续失败 | 用已获取的数据创作，整体降级 | 开头标注"受限于数据可用性，以下为有限数据分析" |

### 5.2 创作阶段

| 场景 | 处理方式 |
|------|---------|
| 素材过少无法达到字数要求 | 保持各类型最低字数下限不变，压缩非核心段落并标注"基于有限公开数据" |
| 找不到经理观点引用 | 不勉强引用，用数据分析替代观点段 |
| 热点话题信息不充分 | 聚焦已知信息，不做过度延伸 |
| 用户要求的主题过于敏感 | 婉拒并建议替代选题 |

### 5.3 排版输出阶段

| 场景 | 降级策略 |
|------|---------|
| ECharts 图表在 HTML 中渲染异常 | 降级为数据表格展示 |
| `RenderEchart` 生成配图失败 | 在 HTML 中内嵌 ECharts 代码；若仍失败降级为表格 |
| 长图生成失败 | 提供 HTML 文件，提示用户使用系统截图或通过浏览器长截图 |
| HTML 文件过大 | 精简图表数量，优先保留核心数据图表 |
