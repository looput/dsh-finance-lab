# 财富目标测算（Wealth Goal Calculator）

## 核心价值定位

- 回答「目标能否达成」「差多少」「增月投/延长期限能否补上」等可量化问题。
- **默认交付 HTML（自包含）**；计算内核在本地脚本，数据可先经 MCP 结构化。
- 与主流程 `wealth-family-advisor` 口径对齐时可作为子模块串联使用。

## 合规边界

- 结论与数字须能追溯到**用户输入、MCP 返回或脚本计算**；禁止编造收益率或目标金额。
- 输出**不构成投资建议**；须有免责声明与风险提示。

---

## 输入层

### 交互流程

```
用户输入（目标/假设） → [可选] MCP 补齐收支与资产 → scripts/run.py → HTML 报告
```

### 输入与意图


| 用户/数据特征 | 处理方式 |
| ------------ | -------- |
| 已给结构化 `goals`（含 PV/PMT/期限/目标金额等） | 直接管道传入 `run.py` |
| 仅口述收支或资产 | 先 `AnalyzeIncomeExpense` / `AnalyzeAssetLiability` 再拼装入参 |
| 要把结论与健康指标联动 | 按需 `AnalyzeFinancialIndicators` |

**必填字段**：`goals`  
**可选**：`income_expenses`、`family_members`（与 MCP 返回对齐）

## 处理层

### （铁律）HTML 交付前置

生成 HTML 前必须遵守 [`HTML视觉模板.md` 开篇「HTML 交付铁律（强制，写死）」](../yingmi-skill/references/HTML视觉模板.md)：**先完整阅读本 `SKILL.md` 及本任务涉及的脚本/引用说明，再完整阅读 `../yingmi-skill/references/demo-report.html` 全文**。`demo-report` **仅作 UI 壳**；**固定板块顺序、测算口径与文案规则**仅以**本 `SKILL.md`** 为准。禁止未读上述文件即交付、禁止照抄 demo 占位数据、禁止自造版式。

### 第零步：加载视觉模板

技术操作见 [HTML 视觉模板 · 生成 HTML 时（操作清单）](../yingmi-skill/references/HTML视觉模板.md#生成-html-时操作清单)；样式源 [`demo-report.html`](../yingmi-skill/references/demo-report.html)。**禁止**改 CSS、**禁止**照抄 demo 示例数值与结论。

### 样式与数据隔离（强约束）

- **壳层规则见「铁律」与第零步；本条约束测算数据：**
- 报告中的金额、达成率、缺口等均须来自**本次**输入或 MCP/脚本结果。
- 缺失字段标注 `数据暂未获取`，禁止用「约」「估计」凑数。
- 输出前做**一致性核验**：Hero、表格、AI 要点中的关键数字一致。

### 第一步：计算与产出

- 复利与达成率定义见下文「计算规则」；实现见 `scripts/compound_interest.py`、入口 `scripts/run.py`。
- 面向用户的默认输出为 **HTML**；链路内可保留 JSON，但不得默认把 JSON 当最终答复。

**计算规则摘要**：  
\(FV = PV(1+r)^n + PMT \cdot \frac{(1+r)^n - 1}{r}\)，其中 \(r=\) 年化/12，\(n=\) 年×12；达成率 = `projected_amount / goal_amount`（上限 1.0）。默认年化 5% 仅在用户未指定时使用并需标注假设。

## 输出规范

### 输出格式


| 条件 | 格式 | 说明 |
| --- | --- | --- |
| 默认 | HTML（自包含） | 与统一视觉模板一致 |
| 用户明确要纯文本 | Markdown | 可降级 |

### 固定板块（顺序固定）

1. Topbar  
2. Hero（目标名称/期限/目标金额/预计终值 KPI）  
3. 💡 AI 核心观点（结论 + 要点 + ⚠️ 风险提示）  
4. 目标测算结果（终值、达成率、缺口）  
5. 替代方案（增月投 / 延期限 / 追加首投）  
6. 多目标汇总（总月投、月结余、可行性）  
7. 免责声明  
8. 页脚  

### 文案口径

- 达成率 ≥ 80%：有望达成；50%～80%：建议增投或延期；< 50%：建议调整目标参数。

### 设计硬规则

1. CSS/主题切换与 `demo-report.html` 一致，**禁止**自造 class 或整页内联样式替代模板。  
2. 完整 `<!DOCTYPE html>…</html>`，含免责声明与页脚。

## MCP 工具配置（P0 必调 / P1 按需）

### P0 工具


| 工具 | 调用时机 | 产出字段 | 触发条件 |
| --- | --- | --- | --- |
| `GetCurrentTime` | 报告生成前 | 当前日期时间 | 统一截止日、页脚日期 |
| `AnalyzeIncomeExpense` | 校验月结余、多目标汇总 | 收入/支出结构、结余率等 | 口述收支需落库或校验 `goals` 与结余 |
| `AnalyzeAssetLiability` | 首投/净资产叙事 | 资产负债分项、净资产 | 需 Hero 或入参中的资产上下文 |

### P1 工具


| 工具 | 调用时机 | 产出字段 | 触发条件 |
| --- | --- | --- | --- |
| `AnalyzeFinancialIndicators` | 与健康度联动解读 | 各项财务指标及状态 | 结论需挂钩储蓄率/杠杆等 |
| `AnalyzeFamilyMembers` | 阶段文案 | 家庭结构、生命周期 | 提供家庭成员且写入结论 |

---

### 运行治理

- **重试与降级**：单工具最多重试 1 次，仍失败则降级输出（已有数据 + 缺失字段标注「数据暂未获取」+ 免责声明）。
- **板块完整性**：输出规范「固定板块」缺一不可；Hero、表格、💡 AI 核心观点中的关键数字须一致。

### 板块完整性自检（必过）

- **失败示例**：缺少 Topbar / Hero / 💡 AI 核心观点 / 免责声明 / 页脚即判定失败。
- **最小可交付骨架（10 行以内）**：

```text
Topbar
Hero
💡 AI 核心观点
目标测算结果
替代方案
多目标汇总
免责声明
页脚（Powered by 盈米MCP · {{日期}}）
```

## 质量标准

- **假设须写明**：默认年化等非用户给定假设须在报告中明确标注。
- **计算可复核**：终值、达成率、缺口须与 `scripts/compound_interest.py` 逻辑一致。
- **免责声明**：每份报告末尾必须出现。

## 错误处理


| 场景           | 处理方式                       |
| ------------ | -------------------------- |
| MCP 工具调用失败 | 已得数据继续测算，缺失项标注，禁止估算填数       |
| `goals` 字段不合法 | 对照入参说明列出缺失键，不输出伪造终值         |
| 脚本执行失败       | 提示检查 `run.py` 与 JSON stdin 格式 |
