# 基金分析决策引擎

## 一、基金类型识别

收到基金代码后，先通过 `BatchGetFundsDetail` 获取基金类型字段，再按下表匹配分析策略。

### 类型识别表

| 基金类型 | 识别信号（类型字段关键词） | 分析侧重 | 可弱化 |
|---------|----------------------|---------|-------|
| 股票型 / 偏股混合 | "股票""偏股混合""灵活配置"（股票仓位 > 60%） | 持仓分析、行业分布、Brinson 归因、选股能力 | 久期、信用评级 |
| 债券型 | "债券""纯债""一级债""二级债""信用债" | 久期、信用评级、Campisi 归因、券种配置 | 重仓股、行业分布（除二级债外） |
| 指数型 | "指数""ETF 联接""被动" | 跟踪误差、费率对比、规模与流动性 | 选股能力、经理风格（被动管理） |
| 货币型 | "货币" | 7 日年化收益率、万份收益、规模稳定性 | 大部分风险指标、持仓明细 |
| QDII | "QDII""国际""全球""海外" | 地区配置、汇率影响、海外市场分析 | 国内行业分布 |
| 偏债混合 / FOF | "偏债混合""FOF""养老目标" | 资产配置比例、子基金分散度、回撤控制 | 单一行业分析 |

### 识别流程（强制）

1. 调用 `BatchGetFundsDetail` 获取基金类型字段
2. 按上表关键词匹配类型（优先精确匹配，如"纯债"优先于"债券"）
3. 若类型字段模糊（如"灵活配置"），再看权益仓位数据判定：
   - 权益仓位 > 60% → 按股票型策略
   - 权益仓位 20%-60% → 按平衡混合策略
   - 权益仓位 < 20% → 按偏债策略
4. 识别结果决定后续调用哪组 MCP 工具

## 二、MCP 工具选择矩阵

### 2.1 基金识别阶段

| 场景 | 工具 | 参数 | 说明 |
|------|------|------|------|
| 用户给了基金代码 | `BatchGetFundsDetail` | `fundCodes: ["代码"]` | 直接获取详情 |
| 用户给了基金名称 | `GuessFundCode` | `fundNameOrCode: "名称"` | 模糊匹配基金代码 |
| 名称匹配不到或需要筛选 | `SearchFunds` | `keyword: "关键词"` | 返回候选列表供用户选择 |

### 2.2 按分析目的选择工具

#### 通用工具（所有类型基金都调）

| 分析目的 | 必调工具 | 可选工具 |
|---------|---------|---------|
| 基本信息 | `BatchGetFundsDetail` | `BatchGetFundNavHistory`（净值走势） |
| 业绩表现 | `GetBatchFundPerformance` | `getFundBenchmarkInfo`（基准对比） |
| 风险评估 | `AnalyzeFundRisk` | `fund-recovery-ability`（回撤修复能力） |
| 交易规则 | `BatchGetFundTradeRules`（op: "allot"） | `BatchGetFundTradeLimit`（限额）、`BatchGetFundsDividendRecord`（分红） |
| 基金诊断 | `GetFundDiagnosis` | — |

#### 股票型 / 偏股混合专用

| 分析目的 | 工具 | 说明 |
|---------|------|------|
| 持仓分析 | `BatchGetFundsHolding` | 十大重仓股 |
| 行业分布 | `getFundIndustryAllocation` | 中信一级行业配置 |
| 行业集中度 | `getFundIndustryConcentration` | 前 1/3/5 大行业集中度 |
| 股票配置指标 | `getStockAllocationAndMetricsByFundCode` | 估值、盈利、抱团股 |
| 行业收益归因 | `getFundIndustryReturns` | 各行业贡献 |
| Brinson 归因 | `getFundBrinsonIndicator` | 行业配置收益 vs 选股收益 |
| 换手率 | `getFundTurnoverRate` | 交易频率 |
| 择时能力 | `getMarketTimingIndicator` | 择时胜率 |
| 权益仓位 | `fund-equity-position` | 仓位水平 |
| 板块偏好 | `fund-sector-preference` | 主板/创业板/科创板偏好 |
| 行业偏好 | `getFundIndustryPreference` | 长期行业偏好趋势 |

#### 债券型专用

| 分析目的 | 工具 | 说明 |
|---------|------|------|
| 持仓分析 | `BatchGetFundsHolding` | 十大重仓债 |
| 债券指标 | `getBondIndicator` | 久期、杠杆、持仓集中度 |
| 券种配置 | `getBondAllocationByFundCode` | 国债/金融债/企业债/同业存单等占比 |
| 信用评级 | `getBondFundCreditRatingLevel` | AAA / AA+ 等评级分布 |
| Campisi 归因 | `getFundCampisiIndicator` | 收入效应/国债效应/利差效应/券种选择 |

#### QDII 专用

| 分析目的 | 工具 | 说明 |
|---------|------|------|
| 地区配置 | `getQdFundAreaAllocation` | 各国/地区配置比例 |
| 持仓分析 | `BatchGetFundsHolding` | 十大重仓股（海外） |

#### 指数型专用

指数型基金分析侧重跟踪效果而非主动管理能力：
- 必调：`BatchGetFundsDetail`（费率）、`GetBatchFundPerformance`（业绩 vs 基准）
- 用 `getFundBenchmarkInfo` 获取跟踪基准
- 跟踪误差从 `GetBatchFundPerformance` 的业绩数据与基准数据差值推算
- 不需要调用归因工具和择时工具

#### 货币型专用

货币型基金分析最简洁：
- 必调：`BatchGetFundsDetail`（7 日年化、万份收益、规模）
- 可选：`BatchGetFundNavHistory`（收益趋势）、`BatchGetFundTradeLimit`（限额）
- 不需要调用：风险评估、持仓分析、归因分析等工具

### 2.3 多基金对比模式

当用户提供多个基金时（≤ 20 只）：
1. 批量调用 `BatchGetFundsDetail`（一次传入所有代码）
2. 批量调用 `GetBatchFundPerformance`
3. 调用 `GetFundsCorrelation` 分析基金间相关性
4. 若用户带金额，可调 `GetFundsBackTest` 做组合回测
5. 输出使用「多基金对比模板」

### 2.4 策略组合分析模式

当用户提到"组合""策略"时：
1. 用 `StrategySearchByKeyword` 搜索策略
2. 用 `GetStrategyDetails` 获取详情
3. 用 `BatchGetStrategiesComposition` 获取持仓明细
4. 用 `GetStrategyAssetClassAnalysis` 看资产大类分布

## 三、数据解读规则

AI 不能只输出数字，必须给出**解读结论**。以下是各类指标的解读标准。

### 3.1 业绩排名解读

| 排名百分位 | 等级 | 解读用语 |
|-----------|------|---------|
| 前 10% | 卓越 | "在同类基金中表现卓越" |
| 前 10-20% | 优秀 | "在同类基金中表现优秀" |
| 前 20-40% | 良好 | "在同类基金中表现良好" |
| 前 40-60% | 中等 | "在同类基金中表现中等" |
| 前 60-80% | 偏弱 | "在同类基金中表现偏弱" |
| 后 20% | 较差 | "在同类基金中表现较差，需关注" |

### 3.2 风险指标解读

| 指标 | 优秀 | 良好 | 一般 | 偏差 |
|------|------|------|------|------|
| 夏普比率（年化） | > 2.0 | 1.0 - 2.0 | 0.5 - 1.0 | < 0.5 |
| 最大回撤（股票型） | < 15% | 15-25% | 25-35% | > 35% |
| 最大回撤（债券型） | < 2% | 2-5% | 5-10% | > 10% |
| 最大回撤（货币型） | 0 | < 0.1% | 0.1-0.5% | > 0.5% |
| 波动率（股票型/年化） | < 15% | 15-22% | 22-30% | > 30% |
| 波动率（债券型/年化） | < 2% | 2-5% | 5-8% | > 8% |

### 3.3 综合评价框架

对每只基金按以下四维度评价，给出综合结论：

| 维度 | 评价依据 | 权重提示 |
|------|---------|---------|
| 收益能力 | 近 1 年/3 年业绩排名 + 超额收益 | 核心指标 |
| 风险控制 | 最大回撤 + 波动率 + 夏普比率 | 核心指标 |
| 稳定性 | 不同时间段排名是否一致，是否大起大落 | 辅助指标 |
| 费用效率 | 管理费 + 托管费 + 申赎费率 | 辅助指标（指数型权重提高） |

### 3.4 收益归因解读

#### Brinson 归因（股票型/偏股混合）

数据来源：`getFundBrinsonIndicator`（默认 timePeriod = LAST_YEAR）

| 归因分量 | 含义 | 解读规则 |
|---------|------|---------|
| 配置收益（AR） | 行业权重偏离基准带来的收益 | AR > 0 → "行业配置优于基准"；AR < 0 → "行业配置拖累收益" |
| 选股收益（SR） | 行业内个股选择的超额收益 | SR > 0 → "选股能力突出"；SR < 0 → "个股选择偏弱" |
| 总超额收益（ER） | AR + SR + 交互项 | ER > 5% → "超额收益显著"；ER ∈ (0, 5%] → "小幅跑赢"；ER ≤ 0 → "未跑赢基准" |

**综合判断模板**：

- AR 为主 + SR 较弱 → "超额收益主要依靠行业配置，选股贡献有限"
- SR 为主 + AR 较弱 → "基金经理选股能力突出，行业配置偏保守"
- AR 和 SR 均正 → "行业配置和选股双轮驱动"
- ER ≤ 0 → "近一年未能跑赢基准，需关注经理策略是否失效"

#### Campisi 归因（债券型）

数据来源：`getFundCampisiIndicator`（默认 timePeriod = LAST_YEAR）

| 归因分量 | 含义 | 解读规则 |
|---------|------|---------|
| 收入效应 | 票息（coupon）收入贡献 | 通常为正且稳定，反映底仓质量 |
| 国债效应 | 利率变动的影响 | 正值 → 久期策略在利率下行中获益；负值 → 利率上行吃亏 |
| 利差效应 | 信用利差变动的贡献 | 正值 → 信用策略获益；负值 → 信用风险暴露吃亏 |
| 券种选择效应 | 个券选择的超额收益 | 反映经理个券分析能力 |
| 超额回报 | 上述效应汇总 | > 0 → "整体跑赢基准"；≤ 0 → "未跑赢基准" |

**综合判断模板**：

- 收入效应占主导 → "收益主要来自票息收入，风格偏稳健持有到期"
- 国债效应显著正 → "久期策略得当，在利率下行周期中捕捉到了资本利得"
- 利差效应显著正 → "信用下沉策略有效，但需关注信用风险敞口"
- 超额回报 ≤ 0 → "近一年未能跑赢基准，需审视久期和信用策略"

### 3.5 投资建议生成规则

投资建议不能空泛（如"建议综合考虑"），必须包含以下结构：

1. **适合的投资者类型**：根据风险等级和波动率判断
   - 低风险 + 低波动 → 稳健型投资者
   - 中风险 + 中波动 → 平衡型投资者
   - 高风险 + 高波动 → 积极型投资者
2. **建议持有期限**：根据基金类型
   - 货币型 → 随时可配
   - 债券型 → 建议 6 个月以上
   - 混合型 → 建议 1 年以上
   - 股票型 → 建议 2-3 年以上
   - 有持有期限制的 → 必须标注锁定期
3. **核心优势**（1-2 条）：从收益、风控、经理能力中选最突出的
4. **主要风险**（1-2 条）：从回撤、波动、集中度、规模中选最需关注的
5. **免责声明**：末尾必须出现

## 四、错误处理与边界场景

### 4.1 基金识别失败

| 场景 | 处理方式 |
|------|---------|
| 基金代码不存在 | 提示"未找到该基金代码，请检查是否正确"，建议用 `SearchFunds` 按名称搜索 |
| 名称匹配到多个基金 | 列出候选列表（代码 + 名称 + 类型），让用户选择 |
| 名称完全匹配不到 | 尝试 `GuessFundCode` 模糊匹配，仍无结果则提示用户核实 |

### 4.2 数据缺失处理

| 场景 | 处理方式 |
|------|---------|
| 新基金（成立不足 1 年） | 不输出近 3 年/5 年等无意义排名，标注"成立不足 X 年，暂无长期数据" |
| 部分指标无数据 | 在对应位置标注"数据暂未披露"，不留空 |
| MCP 工具调用失败 | 用已获取的数据先输出报告，在缺失部分标注"该数据获取失败，建议稍后重试" |
| 基金已清盘 | 提示"该基金已清盘/终止运作"，仅展示历史数据 |
| 基金暂停交易 | 正常分析，但在交易规则部分标注当前交易状态 |

### 4.3 特殊场景处理

| 场景 | 处理方式 |
|------|---------|
| 基金经理变更 | 标注变更时间，提示"当前经理任职时间较短，历史业绩主要反映前任经理表现" |
| 基金规模过小（< 1 亿） | 在风险提示中加入"规模较小，存在清盘风险" |
| 基金规模过大（> 500 亿） | 在分析中提及"规模较大，灵活性可能受限" |
| 分级基金 / 特殊品种 | 标注产品特殊性，提示投资者注意 |

### 4.4 MCP 工具调用异常

| 场景 | 处理方式 |
|------|---------|
| 单个工具调用超时 | 跳过该工具，用已获取数据输出报告，在对应区域标注"数据获取超时，建议稍后重试" |
| 多个工具连续失败 | 输出已获取的基本信息，整体标注"部分数据源暂时不可用，以下为有限数据分析" |
| 批量接口超出 20 只上限 | 分批调用（每批 ≤ 20），合并结果后输出 |
| 工具返回空数据 | 区分"真的没有数据"和"接口异常"：若基金存在但数据为空，标注"数据暂未披露" |
